If you only prep ten

The ten questions most likely to open a judge round, with the answer that closes each one.

1Why is this called a Harness?

Safety-harness metaphor — restrains what the AI can touch. No connection to Harness the company.

It's a safety-harness metaphor, not a reference to Harness the CI/CD company — there's no sponsor tie-in in the code. From the README: "AI provides intelligence. The harness provides trust boundaries. Deterministic code provides authority." The harness restrains what the AI is allowed to touch, the way a climbing harness restrains a fall.

2Why not let the LLM make the decision directly?

The Controller decides — a ~40-line deterministic state machine, no model call inside it, ever.

Because an LLM can be unavailable, malformed, or confidently wrong, and none of those failure modes should be able to move a real truck's cooling system. The Controller is a ~40-line deterministic state machine over (gate result, critic result) — three states, first match wins, no model call inside it. The model's opinion is one input to a decision it never makes.

3What makes this different from a fleet dashboard?

A dashboard shows data; this decides what's trustworthy, checks the AI's reasoning, and gates the one action a human must approve.

A dashboard shows you data. This decides — deterministically — whether evidence is trustworthy, whether an AI risk read is internally consistent with that evidence, and whether an action gets requested at all, then hands the one action that can happen to a human for approval. The product is the boundary around the AI, not the AI itself.

4How does your Trust Gate work?

4 stages: schema check → freshness (<120s fresh) → provenance (right source) → normalize (dedupe to freshest).

Four deterministic stages before anything reaches the model: schema validation, a freshness check (fresh <120s / stale 120–300s / invalid ≥300s, excluded), a provenance check (each signal has exactly one authorized source agent — wrong-source readings are dropped even if an agent were compromised), and a normalizer that keeps only the freshest reading per signal so the confidence denominator can't be inflated by duplicates.

5Why use multiple agents?

Two agents, disjoint scopes — isolation enforced by the absence of an import, not by a permission check.

Two agents, VehicleObserver and EnvironmentObserver, each reads a disjoint slice of world state and holds no reference to the other, to the critic, or to any action function. That's not a convention — it's the absence of an import, verified at runtime by an AST probe and enforced by a dedicated isolation test. It demonstrates least-privilege by construction, not by policy.

6How do you prevent hallucinations from causing unsafe actions?

Gate the evidence → schema-validate the output → Verifier cross-checks claims → Controller can only halt, never act.

Four independent layers, each of which alone would catch a large class of failure: the Trust Gate excludes bad evidence before the model sees it; the model's output must satisfy a strict schema (extra="forbid") or it's rejected outright, never coerced; a Verifier re-checks the model's claims against the same trusted evidence (self-consistency, evidence grounding, contradiction support); and the Controller can only halt or continue — it cannot execute anything the model said.

7What's deterministic vs. AI-driven?

Only the Critic calls an LLM; gate, correlation, verifier, controller, confidence, and policy are all plain deterministic code.

Deterministic: the Trust Gate, the Correlation Engine, the Verifier, the Controller, confidence scoring, and policy packs — none of these call a model. AI: exactly one component, the Critic/Risk Assessment Engine, and even it only ever sees pre-gated structured evidence, never raw telemetry, tools, or an action reference.

8How would this scale beyond a single truck or fleet?

Single-process SQLite today, by design — RunState and the Event Bus already draw the service boundaries for later.

Honestly: today it's a single-process FastAPI service over SQLite — a deliberate hackathon posture, documented as such in the code. The scaling path is architecturally clean because every stage already writes into one RunState through an event bus: swap SQLite for Postgres, move the Supervisor's per-vehicle runs onto a worker queue, and the Trust Gate / Critic / Controller boundaries become service boundaries with no interface change.

9Why build your own runtime instead of an existing agent framework?

Because "the model cannot act" has to be a framework-level guarantee here, not an app-level convention bolted onto one.

Because the entire point is a runtime where the framework itself enforces "the model cannot act" — that has to be a first-class guarantee of the harness, not a convention layered on top of a general-purpose agent framework. A shared RunState, an event bus, a bounded retry engine and a cross-run circuit breaker are ~10 small, readable, individually-tested modules; that legibility is the pitch.

10If you had another month, what would you improve?

In order: real user auth, a true re-execution replay, and persistence beyond single-process SQLite.

Three honest gaps, in order: add real user auth (there's currently none — open CORS, no login, by design for a demo); make "replay" actually re-execute the pipeline against historical evidence instead of re-presenting stored trace data at recorded pace; and move persistence off single-process SQLite so multiple fleets can run concurrently.

Handle-with-care say this straight

Five things the code does not support. Every one of these was checked against the implementation — the honest answer is better than the confident wrong one.

nuance

"Parallel" agents run sequentially in code. The Planner marks both agents safe to run concurrently because their scopes are provably disjoint — but Supervisor._observe() currently calls them in a plain Python for loop, not threads or async. If pressed: "the architecture guarantees it's safe to parallelize; the current implementation hasn't needed to yet."

Replay re-presents, it doesn't re-execute. The Audit Logs page replays a stored decision trace at its recorded stage durations. There's no backend endpoint that reruns the pipeline against historical raw evidence — replay is of already-computed results, not a re-computation.

There is no user authentication. No login, no session, CORS wide open (allow_origins=["*"]). This is an explicit demo posture — say so plainly rather than let a judge discover it by asking to log in.

No named "prompt-injection defense." The defense is structural, not a filter: the Critic only ever receives a small structured JSON array (never free text, never tool access), and its only possible output is a schema-validated RiskMatrix that a Verifier checks before a state machine even looks at it. Frame it as "reduces blast radius by construction," not "we filter injections."

No Harness Inc. connection. Grepped for it — nothing. If asked directly, say so; don't imply a sponsor relationship that isn't there.
